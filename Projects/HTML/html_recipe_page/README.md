# HTML Recipe Page

## Stage 2: Semantic page structure

Build a small, multi-page recipe website to practice structuring content with meaningful HTML. The main goal is to choose semantic elements that describe each page region and its content, instead of using `<div>` for everything.

### What to practice

- Landmark elements such as `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<aside>`, and `<footer>`.
- Ordered, unordered, and description lists where they fit the content.
- Relative links between project pages and absolute links to external sites.
- Internal anchor links that jump to sections on a page.
- `<div>` and `<span>` only when no semantic element fits.

## Project checklist

- [x] Create at least three pages: a home page, a recipe detail page, and an about/contact page.
- [x] Add a shared navigation menu to every page, with working relative links.
- [x] Structure the recipe content as an article.
- [x] Present ingredients in a list and cooking instructions as numbered steps.
- [x] Include preparation time, cooking time, and servings.
- [x] Add a related-recipes aside.
- [x] Add a table of contents with anchor links to recipe sections.
- [ ] Use meaningful filenames and check that all links work.
- [ ] Review each page and choose semantic elements for its major regions.
- [ ] 🍾 Project Complete! 🍾

## Stage 2 mastery check

I can explain why each major page region uses its chosen semantic element, and I can build the recipe site without relying on `<div>` for everything.
